Unknown is a state, too

Why unanswered, negative, and confirmed values need different meanings in an agent workflow.

By Yogesh Singh Engineering notes

Synthetic examples.
No patient information.

A small distinction with a large effect

Consider a synthetic benefits conversation. An agent asks whether a requirement applies. The representative has not answered yet. Encoding that state as “no” changes its meaning: the workflow may skip questions that still need to be asked.

Preserve three states

  • Unknown: the system has not established an answer.
  • Negative: the representative explicitly says the condition does not apply.
  • Affirmative: the representative confirms that it does.

These distinctions need to survive extraction, validation, persistence, and rendering. A correct prompt cannot compensate for a downstream layer that treats a missing value as a confirmed negative.

Test the boundaries

Useful regression cases include an unanswered question, a volunteered answer, an explicit negative, and a correction to an earlier answer. Check which question comes next and what the resulting data means.

Missing information is information about the state of the conversation.
