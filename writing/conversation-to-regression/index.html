From a failed conversation to a regression test

A practical way to narrow failures across prompts, extraction, and decision rules.

By Yogesh Singh Engineering notes

Synthetic examples.
No patient information.

Start with the observable failure

“The agent was confused” is hard to test. “The agent asked again after the representative had answered” is a behavior you can investigate.

Find the boundary that failed

Check the conversation, the extracted state, and the rule selecting the next action. Was the answer missed? Was it stored under a different field? Did the next-question logic ignore it?

Choose the smallest useful test

A deterministic rule can often be pinned with a unit or scenario test. A prompt-render test verifies what instructions the model receives. A model-dependent behavior needs an evaluation of its responses, including repeated runs when variability matters.

Keep the surrounding contract in view

After fixing the immediate failure, check that the output and downstream completion criteria still agree. An agent that stops asking a question must not silently lose information required by the next system.

Use synthetic or appropriately redacted examples when documenting the failure. Keep only the context needed to explain and reproduce it.
