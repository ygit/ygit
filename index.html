How I work

01 / Understand the workflow

Start with the real operating constraints.

I translate payer processes, incomplete answers, and corrections into explicit questions, field definitions, and completion rules. My SDK background also includes working directly with engineers integrating software into their products.

02 / Follow the data

Own the behavior across boundaries.

I trace a change through the conversation, extraction, shared Python/TypeScript logic, and saved output. This is where a locally correct fix can still produce the wrong product outcome.

03 / Make the evidence useful

Reproduce, test, and explain the result.

I build replay tools and regressions, compare against the baseline, and use ablation when a fix spans components. I separate what a test proves from what still needs live verification.
