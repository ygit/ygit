The problem

A “not covered” answer was not always the end of a useful benefits-verification call. A payer representative might offer prior authorization, an exception request, or an appeal. A linear script could miss that route—or mix two different processes together.

What I built

At 100ms, I implemented benefits-verification behavior within the team’s production voice-agent platform. I connected the spoken workflow to structured extraction, question planning, completion rules, and resumed-call summaries.

Engineering decisions

Follow the process the payer actually describes.

I implemented a recovery cascade for non-covered drugs, keeping prior authorization (PA), exception requests, and their appeals in separate paths. When valid recovery establishes coverage, the agent returns to the remaining benefit questions.

Share the rule behind the question.

Shared appeal modules and explicit field mappings keep the conversational path aligned with Python and TypeScript grading. A question should stop being required for the same reason that the agent stops asking it.

Design for answers that arrive asynchronously.

The foreground model can render the next turn before background extraction commits the latest answer. I account for that lag in gates, replay scenarios, and resumed-call behavior.

Results & verification

The original recovery change was checked with question-to-schema validation, shared scenarios, and Python/TypeScript engine suites. Later appeal work added repeated prompt replays and audio-flow tests.

These checks cover different revisions. Live verification and Cekura remeasurement were not established for every rollout, and the final strengthened audio revision still needed a rerun.

A voice workflow is complete only when the conversation and the saved record follow the same rules.
