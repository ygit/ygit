The problem

After learning that an exception request had never been filed, the agent could still ask whether its appeal had been filed. Appeal availability opened the question module, while the grading engine separately required the answer. A prompt-only correction would leave those rules inconsistent.

What I built

I changed the shared eligibility condition in the question plan and grading engines, reconstructed the triggering conversation state, and strengthened regression coverage. I also built local call-replay tooling and contributed PHI-redacted transcript access for audit reviews.

Engineering decisions

Reproduce the actual state at the failing turn.

Tests included rendered prompts, prior-call context, and the one-turn extraction lag. Seeding every final value before the next response would miss the behavior that triggered the failure.

Require the test to exercise the failure.

A response must make useful progress. Empty output does not count as success, and a full-flow test that never reaches the triggering state is inconclusive.

Remove each part of the fix to test its necessity.

Ablations reverted the question-plan change and the engine change separately. Both produced failures, showing that the two changes were needed for the observed result.

Results & verification

Historical selected prompt replays

32 / 120 → 0 / 240

Inappropriate appeal asks: baseline versus fix. Repeated scenarios are not independent production cases.

An earlier full-audio test recorded five baseline failures and five fix passes. The strengthened final audio test was not rerun, live extraction had limited repetition, and Cekura execution was not established for this change.

I keep deterministic checks, real-model responses, focused regressions, full-flow tests, and scenario evaluations separate so that one green layer cannot conceal a missing one.

A passing test is useful only if it reaches the changed behavior and still requires a meaningful response.
