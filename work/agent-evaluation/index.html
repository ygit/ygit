Replaying and evaluating agent failures

Connecting conversation failures to reproducible checks and PHI-aware review tools.

Context Engineering at 100ms

Focus Replay tooling · Evaluation · Privacy

Scope Selected contributions; conceptual descriptions.

The problem

When a voice call produces an unexpected outcome, the cause can sit in the conversation, extracted state, or downstream decision rules. Looking only at the final result leaves much of that context hidden.

My contribution

I built tooling to grade a real call against a local decision-engine build before deployment. I also work on regression coverage, case-summary behavior, missing-data evaluation cases, and PHI-redacted transcript access for audit tooling.

A useful debugging loop

  1. Identify the unexpected behavior.
  2. Compare the stored output with the conversation context.
  3. Evaluate the proposed decision-engine behavior locally.
  4. Inspect required fields and the rule that decided the outcome.
  5. Add a focused regression case.

Evaluation across layers

Unit and scenario tests help pin deterministic behavior. Prompt and conversation evaluations address model-dependent behavior. Cekura and Langfuse are part of the broader toolkit I work with for agent testing, prompt workflows, and tracing.

Privacy is part of debugging

Healthcare transcripts can contain protected health information. I have implemented redacted transcript access for audit tooling so reviews can retain useful context while limiting exposure of sensitive details.

What this work enables

Engine changes can be examined against prior calls before deployment, and missing-data cases can be represented explicitly in evaluation datasets. Failures become inputs to a repeatable engineering process.

A good debugging tool explains why the result happened.

This overview uses no patient data or production transcripts.

Different checks answer different questions

  • Unit and scenario tests: does a known input produce the expected deterministic decision?
  • Prompt-render tests: does the model receive the intended question and condition?
  • Extraction regressions: does an answer populate the right field without inventing unsupported information?
  • Conversation evaluations: does the agent’s next response behave as intended across representative scenarios?

I work with pytest, Cekura, and Langfuse across these layers. Repeated model evaluations matter because a single response does not establish how consistently a prompt behaves.

Operational signals and sensitive data

The surrounding toolkit includes Grafana and Prometheus for metrics, OpenTelemetry and New Relic for diagnostics, and BigQuery for audit analysis. These help narrow a failure before looking at conversation-level evidence.

My PHI-redacted transcript work provides a separate review surface for sensitive conversations. It is a specific engineering control, not a claim that every log or integration is automatically free of sensitive information.
