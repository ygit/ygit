The problem

Customer programs could share the same agent, so an agent identifier was not enough to target a feature. Live calls also carried program metadata that later saved-record recomputation might not have.

What I built

I implemented program-scoped applicability with compatibility fallback and Python/TypeScript parity. As the intended scope expanded, I removed recovery allowlists across the pharmacy benefits-verification workflow.

Engineering decisions

Prefer explicit identity over a broad fallback.

When a program slug is present, it is authoritative. Agent-group membership is used only when that identity is missing, so a fallback does not override explicit program intent.

Follow the policy into every consumer.

The later workflow-wide change covered conversation, resume behavior, derivation, and grading. Removing one gate would leave other paths applying the old scope.

Separate implementation from release evidence.

A merged change, a deployed service, an updated consumer, and a verified live call are different milestones. I describe the evidence available at each layer.

Results & verification

Historical scoping checks included Python/TypeScript engine suites and build/type checks. The later workflow-wide change recorded 172 targeted regressions alongside both engine suites.

Live prompt verification remained pending for that rollout. A Cekura specification was present, but did not establish that remote evaluators had been created or run.

A rollout rule needs to remain understandable even when the next system has less context.
