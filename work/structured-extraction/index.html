The problem

The extracted output was valid JSON, but it could still say something the representative never confirmed. Prior-authorization statuses, dates, and reference numbers were being copied into exception fields, making one request look like two.

What I built

I implemented a route-aware correction, integrated it into the live agent and both grading runtimes, and added regression coverage for copied values, legitimate separate exceptions, and carried state.

Engineering decisions

Trace the complete extraction path.

Field groups were extracted in separate model calls. Instructions in one group were invisible to another. This explained why a correct conversation or a corrected coverage prompt could still produce a wrong saved record.

Make the cleanup narrow enough to preserve real evidence.

On the PA route, the correction checks matching statuses and non-conflicting references for a copied record. Where no exception status exists, it clears only exact PA twins. Different statuses or conflicting references preserve a separate exception.

Apply validation before downstream inference.

The correction runs before PA relabeling and coverage inference. I kept its behavior consistent across live lifecycle hooks and direct Python/TypeScript grading entry points.

Results & verification

Historical offline replay

1,346 calls → 33 corrected records

163 copied field values cleared, with zero disposition-code changes in that sample.

Focused coverage included 29 tests per engine runtime and eight live-agent tests. Released-text extraction measurements recorded 48/50 passes; a timeout/fallback and an empty extraction remained visible in the results.

The replay measures the correction on saved snapshots, not a production improvement rate. The copy detector is a scoped heuristic; separately supported values can sometimes match.

Schema validation checks the shape of an answer. Semantic validation checks whether the fields tell the right story.
