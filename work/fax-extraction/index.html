The problem

Referral faxes combine scanned text, document layout, demographic fields, and clinical context. Producing valid JSON is only the first step: a system also needs to distinguish what the document says from what a model inferred, and expose uncertainty before downstream processing relies on it.

What I built

I implemented a Go-based fax extraction service with OCR and model-based field extraction, integrated with Temporal activities. I later added a reviewer using a different model provider, confidence handling, review diagnostics, and tests around the service and workflow boundaries.

The pipeline used layout-preserving OCR from LLMWhisperer and supported OpenAI and Gemini extraction paths. My review work included Gemini integration through Vertex AI and calibration changes to make uncertainty explicit in the reviewer’s response.

Conceptual pipeline

  1. Read the fax and preserve its layout during OCR.
  2. Extract typed fields and model-reported confidence.
  3. Review the source text and extracted fields with another model.
  4. Normalize scores and preserve disagreement and uncertainty reasons.
  5. Return structured results and separate review diagnostics to the workflow.

Engineering decisions

Reduce anchoring in the review.

The reviewer sees the original OCR text and extracted fields, with confidence scores and derived fields removed. It makes its own determination about the document before reporting agreement. This gives it a different task from simply approving the first model’s answer.

Do not average away a weak signal.

I combined extractor and reviewer confidence using a harmonic mean and capped the combined score when important determinations disagreed. The implementation also normalizes confidence representations and records uncertainty reasons. These are decision signals from models, not calibrated probabilities of correctness.

Keep review status separate from extraction output.

A review can complete, fail, or be skipped. Those states remain explicit, including when configured failure handling allows extraction to continue. Detailed diagnostics are stored separately from the main extracted fields, so a missing review is not silently presented as agreement.

Account for workflow compatibility.

The extraction service sits inside a long-running Temporal workflow. My changes included workflow integration and version-gated behavior so new confidence handling could coexist with existing execution histories.

Validation and result

The implementation includes reviewer-contract tests that inspect the actual request payload, tests for score normalization and combination, and activity/workflow tests for review outcomes. The contract checks specifically verify that extractor confidence and selected derived fields are absent from the reviewer input.

This work produced an extraction pipeline with independently generated review signals and inspectable disagreement. It does not establish a production accuracy rate or a measured reduction in human review; those require a labeled dataset and operational measurements beyond the implementation evidence.

Independent review is useful when it can disagree for a reason—and the system preserves that reason.
