My work at 100ms

Before moving into healthcare voice AI, I built live audio/video and streaming SDKs for iOS, Flutter, and React Native . My responsibilities included iOS frameworks engineering and engineering management for React Native and Flutter.

The developer-facing boundary

A communication SDK exposes operations such as joining a session and changing local media state, then reports events back to the application. Developers need an API they can integrate into their own navigation, state handling, and UI.

The public 100ms iOS quickstart demonstrates this boundary: install the SDK, configure camera and microphone permissions, join using a configuration, and handle updates. It supports distribution through Swift Package Manager and CocoaPods . These are public product capabilities; the links below show the current integration examples.

Across native and cross-platform applications

The application surfaces differ across Swift, Flutter, and React Native , while users expect a coherent audio/video experience. My engineering and management work spanned these SDK surfaces. The useful questions are concrete: what state does the application receive, how does it react to an event, and how does the integration fit the application lifecycle?

Operating SDKs at CleverTap and WebEngage

At CleverTap and WebEngage , I built, deployed, and monitored iOS SDKs integrated into large-scale applications around the world. The work continued after a release: monitoring SDK behavior and working with the engineers integrating it into their products.

I collaborated with cross-platform teams and supported different iOS configurations and mobile applications spanning iOS, Android, React Native, and Flutter . My core responsibility was the iOS SDK; the surrounding integration work required understanding how it behaved inside those different application setups.

This adds an operational dimension to framework engineering: the API needs to be usable, the release needs to reach integrators, and failures need enough diagnostic context for teams to investigate together.

Related experience at Haptik

My earlier work included commercial iOS frameworks, MQTT messaging, Core Data migration, and background processing . I discussed that work in public talks on building commercial frameworks and using MQTT for real-time chat.

That history connects SDK engineering with my current voice-AI work: both require careful handling of state, asynchronous events, and data passed between components.
