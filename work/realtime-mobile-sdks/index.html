Building the 100ms SDKs

I built the WebRTC-based iOS SDK from scratch as part of a two-person team. The product covered live audio/video, HLS and RTMP streaming, chat, screen sharing, and interactive features such as whiteboards, polls, and quizzes, with call-reliability and analytics capabilities.

I then started the Flutter and React Native SDKs while managing three engineers and contributing to the iOS and Android SDKs. This combined hands-on framework work with responsibility for delivering developer-facing APIs across platforms.

CleverTap: geofencing and SDK quality

At CleverTap, I built the geofencing module using Apple’s Core Location framework. It gave the iOS SDK a reusable location-based capability that application teams could integrate into their own products.

I introduced unit and behavioral testing with Quick, Nimble, and OCMock, led integration of Bitrise and CodeBeat, and worked on features across Flutter, React Native, Unity, Cordova, Segment, and mParticle integrations. I also built demo applications for native and hybrid SDK capabilities.

WebEngage: tools for the engineers using the SDK

I implemented asynchronous initialization with Grand Central Dispatch and built the “Doctor” application to help debug SDK behavior. I standardized integration documentation for native and hybrid SDKs and created demo apps showing how to use the APIs.

I also automated SDK deployment with Fastlane and Bitrise. The work connected runtime behavior, integration support, and release delivery: a developer needed to understand the API, observe what happened inside their app, and adopt a new version reliably.

Haptik: turn a product into a reusable SDK

I led the iOS team responsible for the consumer application and commercial framework. I built the SDK from scratch and converted the original application into a client of it, so shared capabilities served both the product and external integrators.

I led the MVVM architecture work and implemented the Core Data stack, MQTT-based messaging improvements, a reusable JSON-driven customization layer, and chat components configurable from a product dashboard.

My work also included a reusable networking client, SSL pinning, payments and cab-booking integrations, analytics, referrals, deep linking, and internal build distribution through Buddybuild and Bitrise.

Inspeero: connected devices and background synchronization

For Electrocompaniet Remote, a mobile interface to a home media system, I implemented multi-context Core Data and background synchronization for a library of more than 10,000 music tracks. The synchronization used GCD and a parent/child context structure to handle library changes alongside the app’s local state.

The application also involved local device discovery, socket communication, gesture-driven interactions, and custom drawing. These were early examples of the asynchronous state and integration problems that later became central to my SDK and voice-AI work.

The common engineering thread

Across these products, the useful work went beyond implementing an API. It included making behavior observable, giving integrators practical examples, keeping application and library state consistent, and building a release process that other teams could use.
