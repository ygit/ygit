The problem

A new Part B verification attempt could inherit another call’s Part D identity, status, dates, and benefit fields. Once those old values entered working context, they could prematurely satisfy question gates or steer the conversation into the wrong plan.

What I built

I changed context initialization for exact traditional Part B inputs, added shared extraction guidance for plan-specific evidence, and tested both the seeded context and the agent’s next response.

Engineering decisions

Scope the reset to the workflow that needs fresh evidence.

For exact traditional Part B inputs, I discarded prior-attempt agent context and initialized from current-call facts. Other workflows retain their existing carry-forward behavior.

Anchor each answer to the requested plan.

Extraction guidance separates Part A, B, and D evidence, while allowing an explicit current-call correction to identify a different plan.

Test state and extraction independently.

Removing stale context fixes one mechanism. It does not establish that every model will select the right date or always return a populated extraction.

Results & verification

Historical checks included 15 real-schema context-seeding tests, 70 focused Part B tests, and 10/10 live next-turn tests across two agents.

Later repeated extraction runs still exposed empty outputs and some incorrect date selections. Those residuals remain distinct from the verified initialization behavior.

Remembering a value and confirming that it applies now are different operations.
