Preventing unsupported coverage conclusions

Traced a false coverage conclusion through deterministic rules and persistence, then fixed the second-pass failure across two runtimes.

The problem

An Unknown coverage value could become Covered merely because a prior-authorization status was present—even “Not Applicable”—despite an explicit non-covered reason. The incorrect conclusion came from ordinary derivation code after extraction.

What I built

I diagnosed the inference and evidence-loss paths, corrected shared Python/TypeScript behavior and live call-end handling, and tested the same records through repeated derivation.

Engineering decisions

Preserve the evidence that blocks an inference.

An initial guard stopped the false conclusion, but a later cleanup removed the non-covered reason from Unknown records. On a second pass, the guard had nothing left to inspect. The complete fix preserves that reason until the appropriate affirmative-Covered conditions apply.

Check legitimate recovery paths separately.

Blocking an unsupported inference must not block an independently established recovery. I kept those paths distinct and aligned the implementations with a shared manifest and scenario corpus.

Replay the saved output, not just the original input.

I derived each snapshot twice with a fixed context. This exposes transformations that look correct in isolation but change their answer after persistence or reprocessing.

Results & verification

Historical offline replay · 743 calls across 259 cases
Implementation False flips, first pass False flips, second pass
Original behavior 10 10
Inference guard alone 0 6
Guard + evidence preservation 0 0

The complete correction produced zero disposition-code changes in this sample. Field-level accuracy and final grading were checked separately, alongside property tests and live-agent parity tests.

These are offline replay results on a defined sample, not a universal guarantee or a measured production success rate.

A correct first pass is not enough when the same record will be processed again.
